4 ประเด็นที่ต้องมีคนตอบ — ไม่ใช่เรื่องเทคนิค แต่เป็นนโยบาย

① ป้าย NC NNNN (เช่น 5ศ 7856, 8ว 7687) ถูกกฎหมายไหม?

ถ้าใช่ → แก้ has_invalid_thai_consonant_placement() rule 4 ให้สอดคล้องกับ is_valid_plate()
ถ้าไม่ใช่ → ต้องเพิ่ม guard ไม่ให้ป้ายที่ box เห็นพยัญชนะถูกกู้คืน (ปัจจุบันโค้ดตั้งสมมติฐานว่า “ใช่” เพราะมี letter-plate guard)

② ยอมให้ระบบ “ไม่ตอบ” ได้ไหม?

ถ้า workflow ปลายทางต้องการคำตอบเสมอ → ต้องเปลี่ยนไปใช้ prior correction แทน (ให้คะแนนหลบคลาสข้อมูลน้อย แต่ยังตอบทุกครั้ง)

③ เปลี่ยนจาก autocontrast เป็น CLAHE ได้ไหม?

CLAHE (clipLimit 2.0, tile 4×4) หรือ autocontrast แบบ masked เฉพาะ ROI ตัวอักษร อาจดีกว่า autocontrast global ที่ทำให้ตัวอักษรจมเมื่อ crop ติดกรอบขาว — แต่ถ้าเลือก ต้องเทรนใหม่ทั้งชุดให้ contract ตรงกัน

④ มีงบเก็บภาพจริงเพิ่ม ~1,000 ภาพไหม?

สำหรับ 36 คลาสจังหวัดที่ขาด (เน้น 12 คลาสที่แย่สุด) — ถ้าไม่มี ต้องยอมรับเพดานที่ต่ำลงและใช้ abstain แทน

Appendix B

Preprocessing contract — 4 วิธีเฉพาะทาง

1 · Smart Padding Homography Crop

ขยาย BBox จาก M1 ออก 12% margin รอบด้านก่อนส่ง Corner Regressor เพื่อไม่ให้มุมป้ายหลุดขอบภาพ

2 · Four-Point Clockwise Quad Sorting

จัดมุม TL → TR → BR → BL ด้วยผลรวม x+y และผลต่าง y−x ก่อน cv2.getPerspectiveTransform — กันมุมสลับที่ทำให้ภาพบิด

3 · Grayscale Smart-Resize + Ambient Background Filling

ถ้าถมขอบดำ โมเดลจังหวัดจะสับสนกับตัวหนังสือ → อ่านค่าสีจากมุมทั้ง 4 ของภาพจริง (np.median(corners)) แล้วใช้สีนั้นเป็นพื้นหลัง canvas padding

ไทย (256, 80) · ลาว (256, 64) · norm 0.5/0.25

4 · Serve-Geometry Upscale (Stage 2 / 3A)

rectified plate 320×160 → 1280×640 ก่อน M2 แล้ว divide boxes กลับรายแกน · char row → 2088×560 ก่อน RF-DETR

ทั้งหมด STRETCH เท่านั้น — ห้าม letterbox/pad เพราะโมเดลเทรนด้วย stretch

ไลบรารีที่ใช้ใน preprocessing

  • OpenCV (cv2) — decoding, BGR→RGB/LAB, CLAHE, perspective transform, deskew
  • NumPy — matrix แปลงพิกัดมุม, vectorization, box sorting, NMS
  • Pillow — resize คุณภาพสูง (BICUBIC), grayscale, dynamic canvas padding
  • TorchVision Transforms — normalization, tensor formatting
