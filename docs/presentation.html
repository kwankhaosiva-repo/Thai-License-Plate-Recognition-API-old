บทที่ 1Chapter 1

ทำไมถึงเริ่มทำ — 3 ข้อจำกัดที่กำหนดทุกการตัดสินใจWhy we started — 3 hard constraints that drove everything

เราไม่ได้เริ่มจากความอยาก “ทดลองโมเดล AI ใหม่ล่าสุด” แต่เริ่มจากโจทย์ธุรกิจจริง: กล้อง CCTV บริเวณทางเข้าอาคารและด่านตรวจจับภาพรถยนต์ที่เคลื่อนที่ ต้องอ่านป้ายทะเบียนไทยและลาวให้ถูกต้อง แล้วส่งต่อเข้าระบบหลังบ้านที่มีอยู่เดิมของลูกค้า ซึ่งเขียนด้วย C# (.NET) We didn't start with wanting to try the newest AI model, but from an industrial need: CCTV gate cameras capturing moving vehicles must recognize Thai and Lao plates accurately and feed into the client's existing backend built on C# (.NET).

โมเดลที่ได้ค่า Benchmark บนกระดาษสูงที่สุดในโลกจะไม่มีประโยชน์ทันที หากติด 1 ใน 3 ข้อจำกัดนี้: A model with the highest paper benchmark is immediately useless if it violates any of these 3 constraints:

① License เชิงพาณิชย์ 100%① 100% Commercial License

ระบบของลูกค้าเป็นซอฟต์แวร์เชิงพาณิชย์ ห้ามติดสัญญาอนุญาตแบบ AGPL-3.0 (เช่น Ultralytics YOLO) และห้ามมีค่า Royalty รายครั้ง ทุกโมเดลและไลบรารีต้องเป็น MIT, Apache-2.0 หรือ BSD-3 เท่านั้น Commercial client system: no AGPL-3.0 copyleft licenses (e.g. Ultralytics YOLO) and no per-unit royalties. All models and libraries must strictly be MIT, Apache-2.0, or BSD-3.

② รันบน CPU ไม่มี GPU② Standard CPU, No GPU

เป้าหมายคือ Edge box และ Cloud Run ที่ไม่มี GPU สำหรับอินเฟอเรนซ์ งบประมาณเวลาทั้งระบบต้องอยู่ภายใน ~75–95 ms ต่อภาพ เพื่อรองรับรถยนต์ที่วิ่งผ่านอย่างต่อเนื่อง Targeted for edge boxes and Cloud Run instances with zero GPUs. The total end-to-end latency budget must strictly remain within ~75–95 ms per frame.

③ ต้อง Export เป็น Pure ONNX ได้③ Pure ONNX Compatible

ต้องรันผ่าน Microsoft.ML.OnnxRuntime (Opset 18) บน C# (.NET) ได้ ห้ามมี Custom C++ Operator เพราะจะทำให้การติดตั้งบนเครื่องปลายทางของลูกค้าล้มเหลว Must run cleanly via Microsoft.ML.OnnxRuntime (Opset 18) in C# (.NET) with zero custom C++ operators to guarantee plug-and-play client deployment.

หลักคิดสำคัญ: “ข้อจำกัดในการ Deploy จริง ต้องเป็นผู้ตัดสินสถาปัตยกรรม ไม่ใช่ Leaderboard” Core Principle: "Deployment constraints must dictate architecture, not the Kaggle leaderboard."
บทที่ 2Chapter 2

เจอปัญหาอะไรบ้าง — บทเรียนจาก 7 ยุคที่ล้มเหลวProblems we hit — lessons from 7 failed eras

เส้นทางสู่ความแม่นยำไม่ได้มาจากการเทรนรอบเดียว นี่คือ 7 อุปสรรคจริงที่เราลองผิดลองถูกและแก้ได้สำเร็จในโค้ด: Accuracy was never achieved on the first try. Here are 7 real-world failures and their definitive engineering solutions:

1
ยุคที่ 1 · เรขาคณิตEra 1 · Geometry

AABB ครอปภาพตรงๆ แล้วส่งอ่านDirect AABB cropping

เมื่อกล้องติดตั้งมุมก้มหรือรถเลี้ยว ป้ายกลายเป็นสี่เหลี่ยมคางหมู ตัวหนังสือถูกบิดยืด อ่านผิดพลาดมากกว่า 40% At tilted camera angles, plates become skewed trapezoids. Distorted letters caused over 40% recognition errors.

แก้:Fix: เปลี่ยนจากครอบตัดตรงๆ มาใช้ Perspective Transform คลี่ภาพป้ายเอียงให้กลับมาขนานในระนาบ 2D เสมอ Replaced direct bounding box cropping with Perspective Transform to flatten skewed plates into rectified 2D planes.
2
ยุคที่ 2 · การ DeployEra 2 · Deployment

Rotated Bounding Box (OBB) ติดหล่ม C++Rotated Bounding Box (OBB) locked in C++

OBB ตรวจจับแผ่นป้ายเอียงได้ดีใน PyTorch แต่ พังตอน Export ONNX เพราะต้องใช้ Rotated NMS ซึ่งเป็น Custom C++ Op รันบน C# ไม่ได้ OBB worked fine in PyTorch but failed at ONNX export due to custom C++ Rotated NMS operators unsupported in standard .NET.

แก้:Fix: 2-Stage Keypoint Regressor: PicoDet-S หา AABB + MobileNetV3 ทายพิกัด 4 จุดมุม แล้วให้ OpenCV ทำ 8-point Homography Warp รัน C# ผ่าน ONNX ได้ทันที 2-Stage Keypoint Regressor: PicoDet-S AABB + MobileNetV3 4-corner regression + OpenCV warp. Pure ONNX compatible.
3
ยุคที่ 3 · สถาปัตยกรรมEra 3 · Architecture

อ่านทั้งป้ายรวดเดียวปนสับสนSingle OCR reading entire plate

ป้ายทะเบียนไทยมี 2 บรรทัด (หมวดอักษร-ตัวเลข ด้านบน และชื่อจังหวัด ด้านล่าง) โมเดล OCR อ่านปนกันเป็นประโยคเดียว หรือสลับบรรทัด Thai plates have 2 tiers: characters on top, province at the bottom. Single OCR read them as one mixed sequence or swapped tiers.

แก้:Fix: เพิ่ม Model 2 (Component Detector) แยกโซน plate_char กับ province ออกจากกันอย่างเด็ดขาด แล้วส่งให้โมเดลเฉพาะทางอ่าน Added Model 2 (Component Detector) to explicitly isolate character and province regions into specialized pipelines.
4
ยุคที่ 4 · กฎเกณฑ์เกินพอดีEra 4 · Flawed Heuristics

พึ่ง DLT Top Banner Code บนป้ายบรรทุกOver-reliance on DLT truck banner codes

พยายามอ่านตัวเลขรหัส 2 หลักข้างคำว่า THAILAND แต่ตัวเลขเล็กมากและมักถูกหัวน็อตเจาะทับ อ่านเพี้ยนแล้วไปทับชื่อจังหวัดที่ถูกต้อง Attempted reading tiny 2-digit truck codes, which were often punctured by bolts, causing hallucinated overrides over correct provinces.

แก้:Fix: ลบโค้ดส่วนนี้ทิ้งทั้งหมด แล้วเปลี่ยนมาเทรน ResNet18 Grayscale ให้จำแนกคำว่าชื่อจังหวัดทั้งแถบโดยตรง Completely stripped the heuristic and trained ResNet18 Grayscale to classify full province strips directly.
5
ยุคที่ 5 · การเดาคำEra 5 · Hallucination

Blind CTC Insertion เติมตัวอักษรผีBlind CTC insertion creating phantom characters

เมื่อกล่องตัวอักษรหายไป ระบบพยายามให้ CTC แทรกตัวอักษรเข้ามา หัวน็อตจึงถูกอ่านเป็นเลข กย 588 → 5กย 4588 When boxes were dropped, CTC blindly inserted characters. Bolts were misread as numbers: กย 588 became 5กย 4588.

แก้:Fix: เพิ่ม DLT Syntax Placement Guard บังคับไวยากรณ์ป้ายทะเบียนไทย ห้ามพยัญชนะอยู่หลังตัวเลข 2 หลัก และห้ามรูปแบบผิดกฎหมาย Implemented DLT Syntax Placement Guard strictly enforcing Thai license syntax rules and rejecting invalid consonant patterns.
6
ยุคที่ 6 · การซ้อนทับEra 6 · Box Merging

Merged Box กลืนตัวอักษรที่ชิดกันMerged boxes swallowing adjacent characters

ตัวอักษรที่ชิดกัน (เช่น 97) ถูก Detector ตรวจเป็นกล่องกว้าง 1 กล่อง แล้ว NMS กลืนกล่องเดี่ยว 2 ตัวข้างในทิ้ง Closely spaced glyphs (e.g. 97) were grouped as one wide box, and standard NMS eliminated the two child boxes inside.

แก้:Fix: Subsumed Composite Box Filter: ตรวจสอบกล่องที่กว้างเกินปกติและครอบกล่องย่อยไว้ ให้ทิ้งกล่องรวมใหญ่เพื่อรักษาตัวอักษรเดี่ยวทั้งคู่ Subsumed Composite Box Filter: detects oversized parent boxes containing child boxes, stripping the composite box to save both characters.
7
ยุคที่ 7 · สัญญาณข้อมูลEra 7 · Contract Mismatch

Train/Serve Crop Geometry MismatchTrain vs Serve Crop Geometry Mismatch

ชุดข้อมูลเทรนเดิมถูกตีกรอบด้วยมือบน Roboflow แต่ระบบ Serve ครอปด้วยสัดส่วนเฉพาะ ทำให้รูปทรงของอักขระบิดเบี้ยวจากที่โมเดลเคยเห็น Original training crops were hand-drawn on Roboflow, while production serving used algorithmic crops, breaking the geometric contract.

แก้:Fix: V2 Pipeline: สกัด crop ข้อมูลเทรนด้วย โค้ดเดียวกันกับที่ Serve ใช้ 100% พร้อมจัดกลุ่มภาพป้องกัน Data Leakage ข้าม Split V2 Pipeline: extracted training crops using the exact same serving code and enforced source-image grouped splits to prevent leakage.
บทที่ 3Chapter 3

ทำไมต้องเป็นวิธีนี้ — Multi-Stage ดีกว่า End-to-End อย่างไรWhy this approach — why Multi-Stage beats End-to-End

ในงานประมวลผลภาษาและภาพ มีแนวคิดหลัก 3 แบบ ซึ่งเราทดสอบและเปรียบเทียบข้อดีข้อเสียอย่างละเอียด: There are 3 competing paradigms for OCR and LPR. We weighed each one against our real-world constraints:

End-to-End Large OCR (Transformer / Vision-LLM)End-to-End Large OCR (Transformer / VLM)

รับภาพแผ่นป้ายแล้วทำนายข้อความออกมาเป็น Sequence ทันที ดูสวยงามและโค้ดน้อย Directly outputs sequence text from raw plate images. Elegant on paper with fewer code lines.

❌ ข้อเสียร้ายแรง: ใช้เวลาอินเฟอเรนซ์บน CPU สูงเกินงบ (~150–350 ms), ต้องการ GPU, และมีโอกาส Hallucinate เดาตัวอักษรที่ไม่มีอยู่จริง เมื่อป้ายมีเงาหรือรอยสกรู ❌ Fatal flaws: Exceeds latency budgets on CPU (~150–350 ms), requires GPU, and suffers from hallucination when encountering shadows or bolt marks.

Single-Stage Rotated Detector (OBB YOLO)Single-Stage Rotated Detector (OBB YOLO)

ตรวจจับแผ่นป้ายและมุมหมุนในโมเดลเดียว หวังจะจบขั้นตอนการ Rectify ในขั้นตอนเดียว Detects plates and rotation angles simultaneously in one model to eliminate multi-step rectification.

❌ ข้อเสียร้ายแรง: ติด Custom C++ Op (Rotated NMS) ไม่สามารถรันบน ONNX Runtime มาตรฐานของ C# .NET ได้ และติดปัญหาลิขสิทธิ์ AGPL ❌ Fatal flaws: Requires custom C++ ops (Rotated NMS), completely breaking vanilla ONNX Runtime on C# .NET, plus AGPL license restrictions.

Multi-Stage Pipeline + Closed-set Classifier (แนวทางของเรา)Multi-Stage Pipeline + Closed-set Classifier (Our Approach)

แบ่งหน้าที่เป็นขั้นตอนย่อย: หาป้าย → ปรับมุมมอง 4 จุด → แยกโซนบรรทัด → ตรวจกล่องตัวอักษร → จัดประเภทแบบ Closed-set (50 คลาสตัวอักษร, 77 คลาสจังหวัด) Deconstructs into explicit stages: Detect plate → 4-point Rectify → Segment zones → Detect char boxes → Closed-set Classification (50 chars, 77 provinces).

✅ ข้อดีเหนือกว่า: ความเร็วอินเฟอเรนซ์บน CPU เพียง ~75–95 ms, แต่ละตัวอักษรใช้เวลาจำแนก <0.5 ms, ควบคุมเรขาคณิตได้ 100%, และ ไม่มีการเดาตัวอักษรผี ✅ Definitive benefits: Blazing ~75–95 ms CPU latency, <0.5 ms per char classification, total geometric control, and zero hallucination.

ความสามารถในการตรวจสอบ (Debuggability)Full Pipeline Debuggability

เมื่อระบบอ่านผิดพลาดในภาพหน้างานจริง เราสามารถตรวจสอบภาพครอปในแต่ละ Stage ได้ทันทีว่าผิดพลาดที่จุดใด (มุมป้ายเพี้ยน, กล่องอักษรหลุด, หรือโมเดลจำแนกผิด) แตกต่างจาก End-to-End Black Box ที่ไม่สามารถระบุสาเหตุได้ When a field image fails, we inspect intermediate crops at each stage (perspective, box recall, or classifier logits), unlike opaque end-to-end black boxes.

Workflow การประมวลผล — จากภาพกล้องสู่ข้อความProcessing Workflow — from raw frame to text

1. ตรวจจับและขยายขอบเขตแผ่นป้าย (Macro Detection)1. Macro Plate Detection with Margin

PicoDet-S หรือ D-FINE Nano สแกนภาพขนาด 640×640 px หาแผ่นป้ายทะเบียน และทำการขยายกรอบสี่เหลี่ยมออก 12% Margin รอบด้าน เพื่อให้แน่ใจว่ามุมของแผ่นป้ายจะไม่หลุดออกนอกกรอบภาพ PicoDet-S or D-FINE Nano detects plate bounds at 640×640 px with an added 12% Margin to guarantee corner points never bleed outside crops.

2. ทำนาย 4 จุดมุม และปรับภาพให้ตรง (Perspective Homography)2. 4-Corner Regression & Homography Rectification

MobileNetV3 Regressor ทำนายพิกัดมุม 4 จุดของป้าย (8 ค่า) จากนั้นจัดเรียงมุมตามเข็มนาฬิกา (TL → TR → BR → BL) และใช้ cv2.warpPerspective คลี่ภาพป้ายเอียงให้กลับมาตรงเป๊ะที่ขนาด 320×160 px MobileNetV3 outputs 4 corner coordinates (8 scalars), sorts them clockwise (TL → TR → BR → BL), and executes cv2.warpPerspective to yield a flat 320×160 px plate.

3. แยกโซนตัวอักษรและจังหวัด (Component Segmentation)3. Tier Segmentation (Characters vs Province)

Model 2 (Component Detector) แบ่งแผ่นป้ายออกเป็น 2 โซนอย่างเด็ดขาด: โซนตัวอักษรด้านบน (ส่งต่อไปยัง Stage 3A) และแถบชื่อจังหวัดด้านล่าง (ส่งต่อไปยัง Stage 3B) Model 2 slices the plate into two distinct regions: character strip on top (to Stage 3A) and province strip at the bottom (to Stage 3B).

4. ตรวจจับกล่องตัวอักษรระดับ Sub-pixel (Char Box Detection)4. Sub-pixel Character Box Detection

D-FINE Small v2 ตรวจจับตำแหน่งตัวอักษรแต่ละตัวบนภาพแถบตัวอักษร ได้ Recall สูงถึง 99.4% จากนั้นใช้ Greedy NMS ร่วมกับ Subsumed Composite Box Filter เพื่อตัดกล่องซ้อนและรักษาตัวอักษรที่ชิดกัน D-FINE Small v2 detects character boxes with 99.4% Recall. Greedy NMS and Subsumed Composite Box Filter clean duplicates while saving adjacent letters.

5. จำแนกตัวอักษรและชื่อจังหวัดแบบ Closed-set5. Closed-set Character & Province Classification

ตัวอักษรแต่ละตัวถูก Pad เป็น 64×64 px และส่งเข้า MobileNetV2 (50 คลาส, ความแม่นยำ 99.86%) ส่วนแถบจังหวัดถูกปรับขนาดเป็น 256×80 px และส่งเข้า ResNet18 Grayscale (77 จังหวัด) Each letter is padded to 64×64 px for MobileNetV2 (50 classes, 99.86% acc). The province strip is formatted to 256×80 px for ResNet18 Grayscale (77 classes).

6. ตรวจสอบกฎไวยากรณ์และส่งออกผลลัพธ์ (Syntax Guard & Output)6. Syntax Rule Guard & Output Formatting

ตรวจสอบลำดับตัวอักษรตามมาตรฐานกรมการขนส่งทางบก (DLT Rules) เพื่อป้องกันการสลับตำแหน่ง และคืนค่าผลลัพธ์ในรูปแบบ JSON สมบูรณ์พร้อมค่า Confidence ในเวลาไม่เกิน 95 ms Validates letter sequences against Thai DLT traffic laws, repairs minor boundary ambiguities, and serves complete JSON outputs within 95 ms.

6 บทเรียนสำคัญที่ตกผลึกจากโครงการ6 Definitive Lessons from the Project

  • 1. ข้อจำกัดการ Deploy เป็นผู้ตัดสินสถาปัตยกรรม: C#/.NET และงบ CPU ตัดโมเดลใหญ่ทิ้งตั้งแต่สัปดาห์แรก 1. Deployment dictates architecture: C# .NET and CPU budgets eliminated complex models early.
  • 2. License เป็นข้อกำหนดทางวิศวกรรม: ตรวจสอบ License ตั้งแต่วันแรก เพื่อไม่ให้ต้องรื้อระบบภายหลัง 2. Licensing is an engineering constraint: Check copyleft on day one to avoid full rewrites later.
  • 3. แบ่งงานให้ถูกสเตจดีกว่าขยายโมเดล: การเพิ่ม Stage แยกโซนแก้ปัญหาที่โมเดลยักษ์แก้ไม่ได้ 3. Explicit stages beat monolithic models: Tier splitting solved issues massive architectures couldn't.
  • 4. ระบบที่ต้องตอบเสมอ จะ Hallucinate: ต้องมี Syntax Guard และทางเลือกสำหรับกรณีอ่านไม่ได้ 4. Models forced to answer will hallucinate: Must enforce syntax rules and allow abstaining.
  • 5. Data-centric ชนะ Architecture-centric: การสร้าง Pipeline ข้อมูลที่ตรงกับ Serving ให้ผลลัพธ์สูงกว่าการจูนไฮเปอร์พารามิเตอร์ 5. Data-centric beats architecture-centric: Aligning train/serve crop geometry boosted accuracy instantly.
  • 6. ตัวเลขที่ซื่อสัตย์ มีค่ากว่าตัวเลขที่สวย: ระบุเงื่อนไขการวัดและ Resolution ให้ชัดเจน เพื่อให้ต่อยอดงานได้จริง 6. Honest metrics beat vanity numbers: Always report test resolution and ground-truth origins.
